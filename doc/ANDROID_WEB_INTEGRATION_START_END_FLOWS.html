CricLeague Flow Diagrams

Android app, Web app, and Android-to-Web integration flows for Live Share and Cloud Sync. Each diagram has explicit start and end states for implementation and testing alignment.

1) Android App Individual Flow (Start to End)

Covers Android user launch, auth/guest path, scoring, optional sync, and match closure.

flowchart TD A0([START: Android app opened]) --> A1{Session available?} A1 -->|No| A2[User chooses Register/Login OR Guest] A1 -->|Yes| A3[Load Home dashboard] A2 --> A3 A3 --> A4[Create/Resume match] A4 --> A5{Mode selected} A5 -->|Offline Nearby| A6[Select role: Broadcaster or Spectator] A5 -->|Cloud account| A7[Load user cloud context] A5 -->|Local only| A8[Start local scoring] A6 --> A8 A7 --> A8 A8 --> A9[Ball-by-ball scoring and events] A9 --> A10{User action} A10 -->|Save & continue later| A11[Persist local state] A10 -->|Finish match| A12[Finalize result and stats] A10 -->|Trigger cloud sync| A13[Queue + send updates] A13 --> A9 A11 --> A14([END: Session paused safely]) A12 --> A15([END: Match completed on Android])

2) Web App Individual Flow (Start to End)

Covers web entry, sign in/guest, Web Score usage, persistence, and completion.

flowchart TD W0([START: Web app loaded]) --> W1{Session token valid?} W1 -->|No| W2[Register / Sign in / Continue as Guest] W1 -->|Yes| W3[Open Home with recent matches] W2 --> W3 W3 --> W4[Start new match or open existing match] W4 --> W5{Scoring path} W5 -->|Full match| W6[Setup teams, toss, innings] W5 -->|Quick Web Score| W7[Simple scoring panel] W6 --> W8[Live scoring timeline] W7 --> W8 W8 --> W9{User exits or completes?} W9 -->|Exit without finish| W10[Auto-save local/browser state] W9 -->|Finish| W11[Lock scorecard + compute summary] W11 --> W12{Logged in user?} W12 -->|Yes| W13[Persist to backend API] W12 -->|No| W14[Keep local-only data] W10 --> W15([END: Match paused on Web]) W13 --> W16([END: Match completed and synced from Web]) W14 --> W17([END: Match completed local-only on Web])

3) Integration Flow - Live Share (Android Broadcaster to Web/Android Spectator)

Shows handshake, share link/session, state broadcasting, spectator updates, and closure.

sequenceDiagram autonumber participant BA as Android Broadcaster participant API as Share API / Session Registry participant SP as Spectator (Web or Android) BA->>BA: START: Host enables Live Share BA->>API: Create share session (matchId, token, meta) API-->>BA: sessionId + shareUrl BA-->>SP: Send shareUrl / code SP->>API: Join request with sessionId/token API-->>SP: Join accepted + initial match snapshot BA-->>SP: Stream incremental scoring updates SP->>SP: Render read-only live scoreboard loop During match BA->>API: Push score events / state updates API-->>SP: Forward latest state end alt Broadcaster ends share BA->>API: Close session API-->>SP: Share ended notification SP->>SP: Freeze on final received state else Spectator disconnects only SP--xAPI: Leave session BA->>API: Continue broadcasting for others end BA->>BA: END: Match complete or sharing stopped

4) Integration Flow - Cloud Sync (Signed User Data)

Covers login, queue/retry, pull/import, conflict-safe update behavior, and final sync state.

sequenceDiagram autonumber participant AD as Android App participant Q as Pending Sync Queue participant API as Cloud API participant DB as Cloud Storage AD->>AD: START: User signs in / session restored AD->>API: Authenticate user API-->>AD: Access token + user context AD->>Q: Enqueue create/update/delete operations loop Sync cycle AD->>Q: Get next pending operation AD->>API: Send operation (PUT-first upsert / delete) API->>DB: Validate owner + apply mutation DB-->>API: Result API-->>AD: Success or retryable failure AD->>Q: Mark done OR retain for retry end AD->>API: Pull latest cloud matches API->>DB: Fetch user match set DB-->>API: Match payloads API-->>AD: Cloud snapshots AD->>AD: Import/merge into local repository AD->>AD: END: Local and cloud states aligned (or queued for later retry)
